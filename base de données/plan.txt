### 1.3 Définition de la variable cible (fraude)
D'après les données, plusieurs indicateurs de fraude existent :

| Colonne candidate | Signification | Utilisation recommandée |
|-------------------|---------------|-------------------------|
| `Dissimulation du Chiffre d'Affaires` (années 2022/2023) | Oui/Non | **Variable primaire** |
| `Probleme de déclaration du Chiffre d'Affaires` | Oui/Non | Variable secondaire |
| `risque de fraude final` | "fraude faible/moyenne/élevée/constant" | Variable tertiaire |
| `Comportement d'anomalie avec l'administration fiscale...` | Oui/Non | Variable de confirmation |

**Recommandation :** Créer une variable binaire `FRAUDE` = 1 si au moins 2 indicateurs sont positifs, ou utiliser le `risque de fraude final` comme cible ordinale.

## 2. Ingénierie des caractéristiques (Feature Engineering)

### 2.1 Variables catégorielles à encoder
| Variable | Encodage suggéré |
|----------|------------------|
| `Personnalité juridique` (Personne morale/physique) | One-hot ou label |
| `Régime 2022/2023` (RSI/HRI/IL/OBNL/REEL/SALARIE) | Target encoding ou one-hot |
| `Profil` (C/PC) | Binaire |
| `Type de centre de rattachement` | One-hot |
| `CRI` (code région) | Target encoding ou one-hot |

### 2.2 Variables numériques transformées
```python
# Créer des ratios pertinents
- Taux d'export = CA Export / CA total
- Taux d'import = Valeur import / CA total  
- Ratio dissimulation = (CA déclaré douane - CA déclaré fiscal) / CA fiscal
- Évolution CA = (CA2023 - CA2022) / CA2022
- Évolution export = (Export2023 - Export2022) / Export2022
```

### 2.3 Variables composites (interactions)
| Interaction | Justification |
|-------------|----------------|
| Régime × CA | Certains régimes sont plus risqués pour certains niveaux de CA |
| CRI × CA export | Les régions frontalières (Extrême-Nord, Est) peuvent avoir plus de fraude |
| Type centre × Profil | Les "non connus" dans DGE/CIME vs CDI |
| Elasticité export × Variation CA | Incohérence entre CA et exportations |

## 4. Modélisation pour la segmentation

### 4.1 Stratégie : Classification supervisée + Clustering

#### Phase 1 - Classification (prédiction de la fraude)
| Modèle | Avantages pour ce contexte |
|--------|---------------------------|
| **Random Forest** | Gère bien les non-linéarités, importance des variables, robuste aux outliers |
| **XGBoost** | Performance élevée, gère les déséquilibres |
| **Régression logistique** | Interprétabilité (important pour la DGI) |

**Approche finale proposée :** Ensemble (Random Forest + XGBoost) avec interprétation via SHAP.

#### Phase 2 - Segmentation non supervisée (clustering)
Pour identifier des "profils types" de fraudeurs :
```python
# Après PCA sur les features pertinentes
from sklearn.cluster import KMeans
kmeans = KMeans(n_clusters=4)  # (fraudeurs avérés, potentiels, à risque, sains)
```

### 4.2 Gestion du déséquilibre des classes
| Technique | Application |
|-----------|-------------|
| SMOTE | Sur-échantillonnage des fraudeurs |
| Class_weight | Paramètre 'balanced' dans les modèles |
| Métriques adaptées | Précision, Rappel, F1-score, AUC-ROC (pas accuracy simple) |

### 5.3 Exemple de code pour la prédiction
```python
import streamlit as st
import pandas as pd
import joblib

@st.cache_resource
def load_model():
    return joblib.load('models/fraud_model.pkl')

def predict_fraud(input_data):
    model = load_model()
    preprocessed = preprocess_input(input_data)
    proba = model.predict_proba(preprocessed)[0, 1]
    risk_level = "Élevé" if proba > 0.7 else "Moyen" if proba > 0.3 else "Faible"
    return proba, risk_level

# Interface
st.title("🔍 Détection de fraude fiscale - Commerce extérieur")
niu = st.text_input("NIU du contribuable")
if st.button("Analyser"):
    with st.spinner("Analyse en cours..."):
        proba, risk = predict_fraud(niu)
        st.metric("Risque de fraude", f"{proba:.1%}")
        st.markdown(f"**Niveau :** {risk}")
```

## 6. Évaluation et validation

### 6.1 Métriques de performance
| Métrique | Cible | Justification |
|----------|-------|---------------|
| Précision (Precision) | > 0.70 | Minimiser les faux positifs (ne pas accuser à tort) |
| Rappel (Recall) | > 0.80 | Maximiser la détection des vrais fraudeurs |
| F1-score | > 0.75 | Équilibre précision/rappel |
| AUC-ROC | > 0.85 | Pouvoir discriminatoire du modèle |

### 6.2 Validation croisée
```python
from sklearn.model_selection import StratifiedKFold, cross_val_score
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
scores = cross_val_score(model, X, y, cv=cv, scoring='f1')
```

### 6.3 Interprétabilité avec SHAP
```python
import shap
explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(X_test)
shap.summary_plot(shap_values, X_test, feature_names=features)
```

## 9. Recommandations additionnelles

### 9.1 Pour améliorer la robustesse
- **Mettre à jour périodiquement** le modèle avec les nouvelles données de contrôle
- **Ajouter un feedback loop** : intégrer les résultats des contrôles douaniers pour réentraîner
- **Créer des profils sectoriels** : le seuil de risque peut varier par secteur d'activité

### 9.2 Pour la DGI
- **Former les agents** à l'interprétation des résultats
- **Intégrer l'outil** dans le workflow existant (pas un outil isolé)
- **Prévoir un comité de validation** pour les cas à risque élevé avant contrôle

### 9.3 Limitations à mentionner
- Le modèle ne remplace pas un contrôle fiscal approfondi
- Il existe un risque de faux positifs/négatifs
- La qualité des prédictions dépend de la qualité des déclarations
